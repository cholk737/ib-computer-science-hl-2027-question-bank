# Preliminary unofficial marking policy

These are authored practice criteria, not official IB criteria. Award whole marks positively up to the part's allocation. Accept equivalent correct terminology and valid alternative implementations. Do not award the same underlying point twice or credit merely repeating information supplied in the prompt.

Algorithm criteria describe credit-worthy logical effects, not a requirement to reproduce the example solution line by line. If the question does not prohibit a built-in function or require a particular algorithm/representation, a correct solution using built-ins remains eligible for full credit. If explicit loops, a named algorithm, supplied helper operations or another constraint are required, alternative solutions must satisfy that requirement. Restrictions must appear in the student prompt, not be introduced only by the markscheme.

Accept consistent follow-through where a method is correct after a previous arithmetic slip. Reject contradicted assertions. Partial credit must reflect demonstrated correct work; a suggested answer's particular names, formatting or harmless implementation choices are not compulsory.

Source markschemes are reference evidence only. Original-source errors and missing uploaded markschemes are recorded separately. All adapted answers must follow the new question's actual data, assumptions and scope, and correct Python/SQL semantics. An example implementation is one valid solution, not the sole valid solution.

The Chunk 2 criteria remain preliminary. Later exam assembly may require reallocating marks and the Chunk 4 independent audit will verify the final question/markscheme pair.
