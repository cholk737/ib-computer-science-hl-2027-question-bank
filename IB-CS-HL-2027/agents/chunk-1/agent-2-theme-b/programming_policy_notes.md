# Theme B programming and scope policy — specialist findings

Source throughout: `sources/2027-guide/Computer-Science-First-Assessment-2027-guide-sbs (1).pdf`. PDF page numbering is one-based; printed guide page = PDF page minus 6. These are unofficial extraction notes, not replacement official guidance.

- **PDF 34 / printed 28:** The scope note defines “may include” as examples that could be assessed, with other examples also possible. “Must include” identifies all examples that will be used in assessment. The exact clause is preserved in `scope_context.json`; do not relabel unqualified guidance or a “such as” phrase as a formal “must include” clause.
- **PDF 14 / printed 8:** Java or Python is the relevant programming language; course material is not specific to one language. Algorithmic thinking includes problem exploration/parameter variation, step documentation, pattern recognition/generalization, and testing/validation. Diagrams and technical documentation are part of these skills.
- **PDF 15 / printed 9:** Code questions have comparable Java/Python versions assessing the same topics, contexts and AOs. Built-in functions can be useful; specific examination prohibitions must be explicit. This project selects Python under the user's instructions.
- **PDF 56 / printed 50:** HL Paper 2 assesses SL and HL Theme B content, 2 hours, 80 marks, 40%; all questions compulsory. Two SL questions recur in HL, including a question focused on algorithmic thinking that requires neither interpreting nor writing code. Additional questions focus on HL-only topics. Python/Java versions and explicit question-specific built-in prohibitions are reiterated. No blanket prohibition is supported.
- **B2.1.1, PDF 44 / printed 38:** The guide lists conceptual data types “Boolean value, char, decimal, integer, string.” Do not infer a new requirement to import Python `decimal.Decimal` or claim Python has a separate built-in `char` type. Preserve the source list; language-specific representations need accurate treatment in question design.
- **B2.1.3, PDF 44 / printed 38:** Required listed failures are unexpected inputs, resource unavailability and logic errors. The Python constructs are `try`/`except` plus `finally`. A logic error need not raise a Python exception; later questions must distinguish defect detection from catchable runtime exceptions.
- **B2.2.2, PDF 45 / printed 39:** 1D/2D Python Lists and adding/removing/traversing a dynamic list are explicit. Java arrays/ArrayLists remain in the source transcription; they are not Python-language requirements.
- **B2.3.2, PDF 45 / printed 39:** Python `if`, `else`, `elif`; the guide's Java `else if` alternative is preserved but is not Python syntax. The listed uppercase Boolean operators express concepts; executable Python uses `and`, `or`, `not`.
- **B2.4.1–B2.4.3, PDF 45–46 / printed 39–40:** Big O time/space analysis, linear/binary search and bubble/selection sort are common SL/HL content. Do not accidentally classify complexity analysis as HL-only.
- **B2.4.4–B2.4.5, PDF 46 / printed 40:** Conceptual recursion includes but is not limited to quicksort and includes binary-tree traversal, fractal images and sorting applications. The separate construction/tracing statement restricts programming to **simple, non-branching** recursive algorithms. Preserve both statements; do not infer a requirement to construct branching quicksort recursion.
- **B2.5.1, PDF 46 / printed 40:** Sequential **text** files; read/write/append modes, read/write/append/close operations. `open`, `read`, `readline`, `write`, `close` are **may include** function examples, not an exhaustive permitted-function whitelist or a requirement to reject valid context-manager code.
- **B3.1.1, PDF 47 / printed 41:** General OOP concepts include inheritance/polymorphism in common content; the detailed multiple-class construction/application content sits in HL-only B3.2. Do not erase the common conceptual requirement.
- **B3.1.3/B3.1.5/B3.2.1/B3.2.2, PDF 47 / printed 41:** Generic language wording includes static/non-static methods/variables, private/public/protected/default access, static polymorphic behaviour. Exact wording is preserved. The guide does not prescribe a Python translation of all Java-like mechanisms. Later Python design/marking must avoid claiming Python privacy conventions equal enforced Java access modifiers or that repeated function definitions provide signature-based method overloading. This is an implementation-calibration flag, not missing extracted text and not grounds to delete the statements.
- **B3.2.5, PDF 47 / printed 41:** Singleton/factory/observer are listed using “such as”; do not convert this into an invented exact three-pattern limit.
- **B4, PDF 48 / printed 42:** The entire topic is HL-only, including all six statements. `dict`/`set` are explicit Python examples in B4.1.6; hashing functions, collision strategies and load factors remain conceptual mechanics. The guide does not require an unsupplied Python interpreter's precise internal hash-table implementation.

No missing or unreadable Theme B statement text was found. A future question-level Python interpretation review is needed for the generic OOP language above; no invented syllabus codes or requirements have been added.
